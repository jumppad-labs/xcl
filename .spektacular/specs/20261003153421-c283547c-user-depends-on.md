## Overview

xcl currently adds the dependencies it works out from references into the dependency list a user writes, so after parsing the two are mixed and the user's own list cannot be shown faithfully. This keeps a user-written dependency list exactly as the user wrote it, shows it in configuration text, and continues to order creation and destruction by every dependency, written or worked out.

## Requirements

- [ ] **User-written dependencies are preserved**
  A dependency list the user writes on an entity holds exactly what the user wrote after parsing, applying and reloading; dependencies xcl works out from references are never added to it.
- [ ] **Ordering still honours every dependency**
  Create and destroy ordering continues to respect both the dependencies the user wrote and those xcl worked out from references.
- [ ] **User-written dependencies appear in output**
  Configuration text shows a user-written dependency list as written, and never shows dependencies xcl worked out itself.
- [ ] **Dependency behaviour is documented**
  The library's documentation and the documentation site's configuration-text guide describe that a written dependency list is preserved as written and that worked-out dependencies are not shown in it.

## Acceptance Criteria

- [ ] **Dependency list unchanged by parsing**
  Given an entity whose user-written dependency list names one entity and whose fields reference a second, after parsing, applying, and reloading from state, the entity's dependency list contains only the first entity.
- [ ] **Ordering covers both kinds of dependency**
  Given an entity A that depends on B only through its written dependency list and on C only through a reference, applying creates B and C before A, and destroying removes A before B and C.
- [ ] **Output shows only written dependencies**
  For the entity above, its configuration text contains a dependency list naming only B; for an entity with no written dependency list, the text contains no dependency list.
- [ ] **Dependency docs updated**
  The library's documentation and the site's configuration-text guide each state that a written dependency list is preserved exactly and shown in configuration text, and that dependencies xcl works out are not added to it.
