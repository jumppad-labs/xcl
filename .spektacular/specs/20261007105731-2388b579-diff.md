## Overview

Diff lets someone using xcl find out what an apply would do before running it. It compares the current configuration against what was last applied, checks existing resources against the real system through its provider, and returns a result describing which resources would be created, changed, replaced or deleted and exactly which values would change, without changing anything. Code built on xcl can inspect that result directly, so tools can show or act on pending changes before an apply.

## Requirements

- [x] **Diff compares configuration with state**
  Users can ask xcl for a diff of a configuration against the saved state, and receive a result describing what an apply of that configuration would do.
- [x] **Diff changes nothing**
  A diff must never create, update or destroy a real resource, and must never write or alter the saved state.
- [x] **Existing resources are refreshed**
  For every resource that exists in state and is still configured, other than one that would be replaced or that depends on a value not yet known, the diff must check the real resource through its provider before deciding whether it would change, so the result reflects the real system rather than only the saved state.
- [x] **New resources are reported**
  A resource that is in the configuration but not in state is reported as one that would be created, along with the values it would be created with.
- [x] **Changed resources are reported**
  A resource whose configuration has changed since the last apply, or whose real counterpart has drifted from it, is reported as one that would be updated.
- [x] **Removed resources are reported**
  A resource that is in state but no longer in the configuration is reported as one that would be deleted.
- [x] **Failed resources are reported as replaced**
  A resource saved as failed, or as failed to destroy, is reported as one that would be replaced (destroyed and created again), matching what apply does with it.
- [x] **Missing real resources are reported as recreated**
  A resource in state whose real counterpart no longer exists is reported as one that would be created again.
- [x] **Field-level changes are reported**
  For every resource reported as updated, the result lists each value that differs, with its value before and after.
- [x] **Unknown values are marked**
  A value that cannot be known until another resource is created is reported as known only after apply.
- [x] **Unchanged resources are only counted**
  Resources that would not change are not listed individually; the result gives only how many there are.
- [x] **Summary counts**
  The result gives the number of resources that would be created, updated, replaced and deleted.
- [x] **Result is inspectable by code**
  Callers can read the result programmatically: each changed resource with its action, and each changed value with its before and after values, without parsing rendered text.
- [x] **Sensitive values stay hidden in the result**
  Sensitive values are masked in the result, including when a sensitive value has changed, unless the caller explicitly asks for them to be revealed.
- [x] **Provider errors are reported**
  When a provider fails while checking a resource, the diff returns an error naming the resource, rather than a result that silently omits it.
- [x] **Diff is observable like other operations**
  A diff reports its progress through the same events and logging as xcl's other operations, so callers can follow it the same way.

## Acceptance Criteria

- [x] **Diff returns a result**
  Given a configuration and saved state, running a diff returns a result and no error; given a configuration identical to an applied one with unchanged real resources, the result lists no changed resources and reports zero to create, update, replace and delete.
- [x] **State is untouched**
  After running a diff, the saved state is byte-for-byte identical to before the diff, including when the diff reports changes.
- [x] **No real resources change**
  During a diff, a test provider records no create, update or destroy calls for any resource.
- [x] **Real resources are checked**
  During a diff, a test provider records a read for every resource present in state that is still in the configuration, is not reported as replaced, and does not depend on an unknown value.
- [x] **Drift is detected**
  When a real resource is altered outside xcl so that its provider reports it as changed, a diff against an unchanged configuration reports that resource as updated.
- [x] **New resource is reported as create**
  Adding a resource to an applied configuration and running a diff reports that resource as created, with its configured values listed.
- [x] **Changed value is reported as update**
  Changing one attribute of an applied resource and running a diff reports that resource as updated, listing exactly that attribute with its old and new values and no other attributes.
- [x] **Removed resource is reported as delete**
  Removing a resource from an applied configuration and running a diff reports that resource as deleted.
- [x] **Failed resource is reported as replace**
  A resource saved as failed, or as failed to destroy, is reported as replaced by a diff, whether or not its configuration changed.
- [x] **Vanished resource is reported as create**
  When the provider reports that a resource in state no longer exists, a diff reports it as created.
- [x] **Unknown values are marked and not read**
  When a resource already in state is changed to reference a newly added resource, a diff reports the referencing value as known only after apply, and the test provider records no read for the referencing resource.
- [x] **Unchanged resources are counted only**
  With one changed and two unchanged resources, the result lists exactly one resource and reports two unchanged.
- [x] **Summary counts match**
  For a configuration that adds two, changes one, replaces one and deletes one resource, the result reports 2 to create, 1 to update, 1 to replace and 1 to delete.
- [x] **Result can be read by code**
  A caller can, without parsing rendered text, enumerate each changed resource's address and action, and each changed value's name, before value and after value.
- [x] **Sensitive values are masked in the result**
  When a sensitive value changes, the result, including its JSON encoding, contains neither the old nor the new value but still records that the sensitive value changed; when the caller asks to reveal sensitive values, both values appear.
- [x] **Provider error fails the diff**
  When a provider returns an error while checking a resource, the diff returns an error that names that resource.
- [x] **Diff emits events**
  A caller subscribed to xcl's events receives start and finish events for the diff operation, and per-resource events for the provider checks it performs.
- [x] **Diff writes logs**
  A diff writes log entries through xcl's configured logger, as apply does.

## Technical Approach

- Reuse the apply walk and the existing provider read and change checks rather than building a separate comparison path, so a diff and an apply cannot disagree about what changes.
- Beyond the referenced design, the detailed design is left for the plan workflow to propose.

## Success Metrics

- For every configuration in the end-to-end suite, the resources a diff reports as created, updated, replaced and deleted match the resources the following apply actually creates, updates, replaces and deletes.
- Running a diff against configurations in the end-to-end suite leaves saved state and real resources unchanged in every case.
- No sensitive value appears in any diff result produced without an explicit request to reveal it.

## Non-Goals

- Rendering the result as text; that is a separate spec in this epic.
- Adding diff output to the `example/` programs; this is left for later.
- A command-line interface; xcl remains a library.
- Saving a diff and later applying exactly that diff.
- Matching list elements by identity rather than by position.
- Showing the saved values of a resource that would be deleted.
- Changes to the VS Code extension.
