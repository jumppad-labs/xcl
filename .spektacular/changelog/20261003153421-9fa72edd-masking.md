# Masking sensitive values in state and events

## What was built

A new public `mask` package makes masking of sensitive values pluggable. A masker implements `mask.Masker` (`Name`, and `Mask`, which turns the JSON of a real value into what is written in its place); a masker that can open what it produced also implements `mask.Reversible`. Four built-ins ship: `mask.EncryptAES256GCM(key)` (reversible, 32-byte key, fresh nonce), `mask.HashHMACSHA256(key)` (one way, deterministic per key), `mask.Omit()` (no value) and `mask.Redact()` (the marker `(sensitive)`). Every masked value is written as an envelope naming its masker, `{"xcl_masked":"<name>","value":<output>}`; `mask.Unmask` opens one only when it can do so faithfully, and otherwise fails with the new `xcl.ErrUnrecoverable`.

In `xclconfig`:
- The internal wire encoder takes an optional masker per call and reports whether it wrote any sensitive value. Provider calls, change detection and conversions keep real values; the state save passes the state masker; event data passes the event masker.
- `xcl.WithStateMask(m)` encrypts every sensitive value saved to state (both the apply save and destroy's per-resource saves) and opens it on load. A one-way or nil masker fails `NewConfig` with the new `xcl.ErrMaskNotReversible`. The saved-entity reader opens envelopes before typing a record; anything it cannot open (wrong key, no masker, other masker) fails the load with `xcl.ErrUnrecoverable` naming the entity and masker, so a secret is never silently replaced. Plain state still loads and is encrypted on the next save.
- Without a state masker, each Apply or Destroy that writes a sensitive value to a store emits one warn-level log event: `sensitive values are stored unencrypted in state; use xcl.WithStateMask to encrypt them`.
- Event data is masked by the event masker, `mask.Redact()` by default; `xcl.WithEventMask(m)` chooses another and `xcl.WithNoEventMask()` sends real values. Errors and log details always show the marker. `EncodeSavedEntity` shows the marker for every masked value.
- The application-config and plugin examples encrypt their state when `XCL_STATE_KEY` holds a base64 32-byte key, and show the warning without it.
- README, `docs/state.md` and `CHANGELOG.md` document all of it, guarded by content tests; the end-to-end leak suite now runs with encrypted state.

In `xcl-website`: the events guide gained a section on sensitive values in event data, and a new State masking page (linked from the Guides navigation and the Sensitive values page) covers encrypting state, the reversible-only rule, the warning and the built-in maskers.

## Why it matters

Sensitive values were already hidden wherever xcl displays them, but state stored them in plain text and events could only ever show the fixed marker. Application developers can now keep secrets out of state files and event pipelines without giving up state, choose how events show sensitive values (for example a keyed hash to correlate them), or explicitly send real values to trusted receivers.

## Deviations from the plan

- `mask` exposes a few helpers beyond the planned surface: `Envelope`, `IsMaskedObject`, `Open` and name constants.
- A nil state masker is rejected by wrapping `ErrMaskNotReversible` rather than with a separate error.
- `parser.DefaultOptions()` also defaults the event masker to `mask.Redact()`, so a standalone parser redacts event data like `Config`.
- The planned test that every lifecycle emission passes the entity was replaced by inspection: every emission carrying data passes it.
- The plugin example tests briefly tolerated the new warning, then were restored to strict once the example took a state key.
- A flaky assertion in `TestPluginEventDataShowsTheMarkerForTheSensitiveInteger` (matching "1234" in a random temp path) now checks only the `pin` field.
- The validation-error leak test with masking off asserts the secret is absent but not the marker, since that error prints no value.
- The CHANGELOG Breaking list names only changes against the last release; the earlier unreleased entry describing bare-marker event data was left as written.
