# Using XCL with Go and Python, and API references on xcl.dev

## What was built

xcl.dev gains two walkthroughs and two generated API references.

- **"Using XCL with Go"** (`/using-xcl-with-go/`) builds one program, `deployer`, from an empty module: entity types as Go structs embedding `types.ResourceBase`, a local registry with `RegisterType` and an application function (`RegisterFunction("slugify", ...)`), `xcl.NewConfig` with a state path and variables, `Validate` with the `ConfigError` problem loop, `ApplyContext` under `signal.NotifyContext`, the function-form lookups (`Find`, `FindByType`, `FindOne`, `All`) and the untyped `FindEntitiesByType`/`Entities`, outputs, `ErrNotFound` and `*NotUniqueError`, a `status` command using `Load`, and `Destroy`. It ends with the full program and links to the language reference, registries, plugin, state and events pages and the Go API reference.
- **"Using XCL with Python"** (`/using-xcl-with-python/`) builds the same program with `xcl-lang`: `@xcl.entity` dataclasses, `LocalRegistry`, the Go Docker plugin installed from its signed GitHub release through `GitHubRegistry`, `xcl.Config` as a context manager, lookups including a plugin entity as `xcl.Entity`, exceptions, `load` and `destroy`, then an asyncio version with `xcl.aio.Config`, an `async def` function, other work running during the apply and cancellation by timeout, and a section on fork safety.
- **API references**: `/api/go/` documents the twelve public Go packages (doc2go v0.12.2, embed mode) and `/api/python/` documents `xcl`, `xcl.aio` and `xcl.mask` (pdoc 16.0.0 with a content-only frame). `npm run api-docs` generates them from the release pinned in `src/config/release.json` (`v0.5.3`, `xcl-lang==0.5.3`), two routes render them inside the site's layout with a dedicated stylesheet, and the deploy workflow sets up Go and Python, generates them before the build, and can be run by hand. The hero badge reads the same pin.
- **Reachability**: the Guides dropdown starts with both guides (its label opens the Go guide), a new "API" dropdown (hidden on phones) follows "Language", the footer links "Go API" and "Python API", and the home page's closing banner and Documentation section offer both guides and both references. The xcl README links both guides, the xcl CHANGELOG records the feature, and the xcl-python README links the Python reference and guide.

Both guides were checked by assembling their snippets in page order in an empty directory and running them against the released v0.5.3 (Go module from the proxy; `xcl-lang` from PyPI with a Docker-compatible engine). The output each page quotes is copied from those runs.

## Why it matters

Developers adopting XCL had no single walkthrough of its API in their language, only topic pages, pkg.go.dev for Go and no hosted reference for Python. Each guide now takes a developer from an empty program to a working one and links out for detail, so a getting-started question can be answered with one link, and the Go API topics cut from the README have a home again. Both references live on xcl.dev in the site's look and always match the release the site advertises.

## Deviations from the plan

- The release is v0.5.3, not v0.5.0: v0.5.0 was already taken, and v0.5.1 and v0.5.2 never reached PyPI.
- The Go program is split into one file per concern so each section adds a whole file with its own imports; the Python program grows one `main.py` plus `main_async.py`.
- Python's `ConfigError` exposes `problems`, not `causes`; `NotUniqueError` carries the count in `details["count"]` (a string).
- The asyncio demo uses a ticker task rather than a small server; cancellation is shown with `asyncio.timeout`.
- Fragment parsing is shared in `src/lib/api-fragments.ts`, and `ApiReference.astro` takes the parsed page and the list of all pages, which it renders as a package or module list in the header. `process.env.CI` is read through `globalThis` because the site has no Node types.
- The guides' install lines read the release pin through expressive-code's `<Code>` component.

## Outstanding
