# Query API v2: asking a configuration for what you want

## What was built

Developers embedding XCL now ask a parsed configuration directly for what they want, in a single
call, and get an honest answer when the question cannot be answered.

**The lookup surface.** Seven operations on the configuration object: one entity by its address,
everything of a given kind, the one entity expected to be unique, everything of a Go type without
naming it as a string, an untyped enumeration of everything declared, every published value keyed by
address, and a conversion from an enumerated entity to a caller's Go type. Each ships twice from one
implementation — as package-level functions that compile on the project's declared minimum Go
version, and as generic methods on the configuration behind a build constraint, because generic
methods require a newer toolchain than the project supports. Neither spelling carries logic, so they
cannot drift; tests assert they return the same pointers and byte-identical errors.

**Values a configuration publishes** are reached by address like anything else, and yield the
resolved value rather than the declaration that produced it. A caller no longer needs to know such
values are held differently in order to ask for one.

**An error vocabulary.** Seven sentinels name every way a lookup can fail, each matched by identity
and each carrying a detail type with the specifics — including how many matched when a
single-expected query found more. An empty result and an unanswerable question are never represented
the same way again. The state layer's existing not-found answers to the same sentinel, so a failure
to find a declared entity reads as one condition wherever it was raised, while the plugin boundary's
not-found — which means the real infrastructure is gone — matches neither.

**The data model underneath.** Every declaration now records the kind of stanza it is and its
specific variety independently, where a single field previously meant different things depending on
the stanza. Addresses carry the variety as their own segment, so an address and a positional query
share one grammar. A top-level item can be declared with its variety as the leading keyword, which is
a genuinely different type with a different address rather than a rewriting of the existing form.

**Storage became storage.** The package that persists a configuration no longer answers questions
about it: it neither parses addresses nor searches, its persistence contract exchanges plain
entities, and its in-memory container is no longer a public type. The configuration object is the
only public query surface.

**Everything bundled and documented moved with it.** All three example programs use the new surface
in the portable form, one demonstrates retrieving a published value by address alone, the library
documentation and all four documentation-site pages describe the surface that now exists, and the
project's own recorded architecture knowledge no longer contradicts the shipped library. A CI job
builds and vets against the declared minimum toolchain on every change.

## Why it matters

The previous surface required constructing a throwaway helper bound to one Go type before every
lookup, and then answered badly. A query for a kind returned an empty result whether or not the
question made sense. A conversion to the wrong type returned a value with half its fields unset
*alongside* its error. A metadata failure was a panic. Retrieving a published value meant knowing how
outputs are stored. Every one of those failures was silent or misleading, and each one is now either
impossible or named.

The two-spellings delivery exists so that capability is not gated on toolchain version: a consumer on
the minimum supported Go can do everything a consumer on the newest can, differing only in spelling.

## Deviations from the plan

- **Phases 1.1 and 1.2 had to land together.** Splitting the metadata field's two axes breaks the
  expression language the moment it happens, because references resolve through that field. The plan
  separated them for reviewability; the suite cannot be green between them. Landed and ticked as one.
- **Milestone 5 was added during implementation**, on the user's decision, after the seam became
  visible: storage should store and retrieve, and the configuration object should be the only public
  query surface. Three phases took the lookups out of storage, narrowed the persistence contract to
  plain entities, and documented the result. This is the only breaking public change, which the
  spec's non-goals permit for an unreleased version.
- **The plan's instructions were wrong in three places, each corrected and recorded.** Four state
  sites were said to need the variety *added* to a comparison; that held for one, because the address
  type carried the identical conflation the metadata did and did not split until a later phase. The
  type registry's creation path was said to serve builtins only; it also served registered Go types.
  And a registration record was described as a parallel map, which scattered type details across
  three places until it was consolidated into one.
- **Three production bugs were introduced by this work and caught by tests, not the compiler.** A
  bare-registered type could never be applied, because the lifecycle read the wrong axis to recognise
  it. The bare keyword acted as an alias for a kind-led type rather than a distinct one. A variety
  that can never be declared was accepted as a valid query. All three are fixed and pinned.
- **Two pre-existing defects were repaired rather than carried over**: a module matcher whose prefix
  was not anchored at a separator, so a query for one module also returned a sibling whose name began
  with the same characters; and a bundled example that documented and was tested for a teardown it
  never performed, which had been failing for three tests since before this work began.
- **`errors.Is` was made to work end to end**, which the plan did not scope. The container returned
  by apply and destroy had no `Unwrap`, and eleven parser sites formatted their cause into a message
  string with `%s` — rendering the text while destroying the identity, which is the exact
  anti-pattern the plan holds up as its cautionary example.
- **One clause of one acceptance criterion is descoped**, recorded in the plan: documentation-site
  samples are not compile-checked. Dropped by user decision during planning. The other clauses of
  that criterion are met and verified.
