# The standard plugin layout, written down

xcl's documentation now describes the one layout every xcl plugin uses: where its block types, providers, backend clients and test doubles, and entry points live, how its files are ordered, how its provider decides between update and replace, and how it is tested. It points plugin authors to the new plugin template repository as the worked example and the place to start. Nothing in xcl's code or API changes.

> Derived from project xcl (github.com/jumppad-labs/xcl), spec/plan 20261009092551-82db0140-plugin-template. See the project-level record for the full feature.

## What changed in this repo

- **`docs/plugin-layout.md` (new):** the layout guide. It covers:
  - the directory tree and what each part holds
  - file order
  - the explicit `Changed`, the told-only `Update` and `Read`
  - tests
  - starting from the template
  - releasing in the asset contract
  - what the layout does not cover
- **Links:**
  - `docs/README.md` links the guide from "Start here".
  - `docs/plugin-developer-guide.md` links the guide and the template in its introduction and in "The example provider".
  - `README.md` has a "Writing a plugin" paragraph in "With plugins".
- **`CHANGELOG.md`:** a new entry for this spec.

## Why

The project wanted one documented plugin shape that the template, the examples and future jumppad ports all follow, so authors and reviewers can tell where any part of a plugin belongs.
