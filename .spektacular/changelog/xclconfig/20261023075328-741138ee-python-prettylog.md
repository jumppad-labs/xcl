# Parity program records Go's pretty log

The parity program that language bindings compare themselves against now also records what Go's example pretty logger writes for each fixture, so the Python pretty logger is held to Go's real output line for line. Nothing in xcl's library or its example changes.

> Derived from project xcl (spektacular), spec/plan 20261023075328-741138ee-python-prettylog. See the project-level record for the full feature.

## What changed in this repo

- `bindings/libxcl/cmd/parity` records a new `pretty_log` key: for a fixture whose apply succeeds, it applies the fixture again in a state directory of its own through `example/prettylog.Handler` at info with processed event data, and records the sorted groups of event lines with the configuration beneath them, colour removed and times, durations and run paths normalised; `null` when the apply fails. `newConfig` accepts extra config options.
- `bindings/libxcl/go.mod` requires `example/prettylog` (replaced to the checkout) with a comment explaining it is needed only by the parity program; charmbracelet/log v0.4.2, lipgloss v1.1.0 and termenv v0.16.0 come in at the example's versions. The shared library does not import them.
- The parity fixtures README documents `pretty_log`; Go tests cover the stage and its normaliser.

## Why

The Python package's new `xcl.prettylog` promises the same lines as Go's example. Recording Go's real output in the parity program lets every binding's parity suite prove it on every shared fixture. A binding pinned to an xcl release needs this stage in that release.
