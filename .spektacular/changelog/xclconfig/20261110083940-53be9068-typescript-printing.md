# The printing design describes how TypeScript errors show their report

The printing and highlighting design now describes how a TypeScript program shows an xcl error's report as built. `console.error` shows it through custom inspection, coloured as Node's console colours the stream. An uncaught error shows it as plain text from the error's `stack`, and no process listener is installed. The design no longer leaves this to be confirmed.

> Derived from project xclconfig (file), spec/plan 20261110083940-53be9068-typescript-printing. See the project-level record for the full feature.

## What changed in this repo

- `.spektacular/design/printing-and-highlighting.md`: the first paragraph of the TypeScript part of "Errors and loggers" is corrected. Node's fatal-exception path calls `inspect` with `customInspect: false`, so the report reaches uncaught output through `stack` instead.

## Why

The TypeScript package's printing work showed that custom inspection is never called for an uncaught error on Node 22, 24 or 26. The design is the shared source for every language's printing, so it now says what the package does. No Go or Python behaviour changed.
