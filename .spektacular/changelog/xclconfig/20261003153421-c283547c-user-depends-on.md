# User-written depends_on lists are kept as written

A `depends_on` list you write now stays exactly as you wrote it, after parsing, after applying and when loaded back from saved state. Dependencies xcl works out from references are no longer added to it, but they still order creation and destruction. Configuration text now shows a written `depends_on` list as written, and none when you wrote none. Saved state no longer records a separate list of parents: destroy order comes from the same dependencies as create order.

> Derived from project xcl (xclconfig), spec/plan 20261003153421-c283547c-user-depends-on. See the project-level record for the full feature.

## What changed in this repo

- **Ordering** (`internal/parser/dag.go`, `util.go`, `destroy.go`, `parser.go`): one builder, `buildDependencyGraph`, orders create and destroy from each entity's `Meta.Links`. Destroy builds it over the saved working state, keeps only edges between the entities being destroyed, ignores a missing parent module, and walks it in reverse. The destroyer is handed the address parser.
- **Types** (`types/resource.go`, `types/resource_helpers.go`): `Meta.Parents` was removed. `AppendUniqueLink` replaces `AppendUniqueDependency`. The doc comments for `DependsOn` and `Links` now describe the split.
- **Parser**: `depends_on` entries are validated and added to the links in canonical form, while `DependsOn` is set to the strings as written. The dead `setDependsOn` TODO block was removed.
- **Configuration text** (`encode.go`): `depends_on` is written when non-empty.
- **Golden schema** (`internal/schema/test_fixtures/embedded.go`): `Parents` was removed in both places.
- **Tests**: new create- and destroy-graph tests, destroy-from-saved-state tests (including across modules and module-relative links), parse/apply/reload `depends_on` tests, encoder tests, `AppendUniqueLink` tests, and a legacy `parents` decode test. The parents tests were rewritten to read the graph built from saved state. There are new fixtures `lifecycle/written_and_referenced` and `lifecycle/module_internal_reference`.
- **Docs**: the README configuration-text section, a CHANGELOG entry with a Breaking list, `docs/state.md`, `docs/overview.md`, `docs/parser-lifecycle.md` and `docs/plugin-developer-guide.md`, with content tests in `readme_test.go`.

**Breaking:** `DependsOn` holds only the written list, so read `Meta.Links` for every dependency. `AppendUniqueDependency` is replaced by `AppendUniqueLink`. `types.Meta.Parents` and `meta.parents` are gone, and older state carrying `parents` still loads with the key ignored. Configuration text includes a written `depends_on`.

## Why

This repo holds the parser, types and encoder that mixed the author's list with worked-out dependencies. Moving ordering onto the links lets the author's list be kept and shown faithfully, and leaves one dependency source and one graph builder for both directions.
