# Replacement and dependency changes

Plugins can now say a change needs the resource rebuilt. Asked whether a resource changed, a plugin answers unchanged, update or replace. It is also told which of the resources it depends on the same apply will update or replace.

An apply decides the outcome of every resource before touching any of them. It then destroys what is being replaced or removed, dependents first, and only then creates and updates in dependency order.

Plans list exactly what the apply will do and say why each replacement happens. In the plugin example, changing the network's address range now really rebuilds the network and its container.

> Derived from project xcl (jumppad-labs/xcl), spec/plan 20261008132354-4538504f-replacement-deps. See the project-level record for the full feature.

## What changed in this repo

**Plugin contract.**
- New public `entity` package: `entity.Change` (`NoChange`, `Update`, `Replace`) and `entity.DependencyChange`.
- `ResourceProvider[T].Changed(ctx, old, new, dependencies []entity.DependencyChange) (entity.Change, error)`.
- The same change runs through `ProviderAdapter`, `Plugin`/`PluginHost`, the direct and gRPC hosts, the gRPC server, `plugins/testing` and the regenerated mock.
- `DefaultChanged` answers update or no change.
- The protocol (`plugins/plugin.proto`, regenerated) gained the `Change` enum, the `DependencyChange` message, `ChangedRequest.dependencies` and `ChangedResponse.change`, with `bool changed` reserved.

**Apply and plan.**
- `Parser.Diff` and `Parser.Apply` share one decide pass. Every saved resource is read and asked `Changed` with its updating or replacing dependencies.
- Dependencies are looked through outputs, variables, modules and config-only types. Resources with unknown inputs are read with saved values and planned as at least an update.
- A failed decision stops before anything changes and saves nothing.
- Apply then:
  1. destroys replaced and removed resources, dependents first, with state saved after each;
  2. creates, updates or keeps every resource as decided, in dependency order.
- Failed creates and destroys are saved `failed` / `destroy_failed` and are replaced on the next apply.
- The decide pass logs its counts and each replacement's reason at debug level.

**Diff.** `diff.Resource` gains `Reason` and `ReplacedDeps` (JSON `reason`, `replaced_dependencies`). `Render` names the cause on the comment line above a `-/+` resource.

**Providers and examples.**
- **Docker network:** answers replace when its subnet changes.
- **Docker container:** answers replace when its image, command, environment or networks change, or when its network is replaced.
- **Template:** answers replace when its destination changes.
- **Person plugin:** answers replace when its name changes.
- **E2e fixtures:** PostgreSQL replaces when its `location` changes, and Ingress when its `hostname` changes.
- **Configuration:** `example/plugin/config/alt.xcl` moved to `example/plugin/config-subnet/main.xcl`, with a `make replace` target.

**Tests.**
- Unit and integration tests for each layer.
- Docker-gated example tests for the subnet change, including the real network range, the new container, the re-rendered template, and no changes afterwards.
- Exact plan-equals-apply e2e comparisons.
- In-process versus external equivalence for the person plugin.

**Docs.** The plugin developer guide, plugins guide, parser lifecycle, state, overview, docs index, README and CHANGELOG are updated.

**Breaking:**
- `Changed` has a new signature and result type, and so do the adapter and host `Changed` methods.
- External plugins must be rebuilt. An old plugin's answer reads as no change, so it would never be updated.
- Compatibility with state saved by the previous version is not guaranteed.
- A `Read` failure while deciding no longer marks the resource failed. A failed or cancelled decide returns no state and saves nothing.
- Resources that read a computed value of an updated or replaced resource are now updated by apply.
- `config/alt.xcl` moved to `config-subnet/main.xcl`.

## Why

Changes a resource could not take in place were silently treated as updates. The real infrastructure drifted from state, and dependents were never told. This repo holds the plugin contract, the parser that decides and acts, the diff renderer and the examples, so it carries the whole behaviour change.
