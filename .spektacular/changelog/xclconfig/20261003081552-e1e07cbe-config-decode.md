# Decode: fill an application struct from a configuration in one call

A configuration can now fill a struct of your own in one call. Slice fields receive every block of their type, in the order the blocks were written, and pointer fields receive the one block of their type. Every other field keeps its value. Entities now come back from every lookup, and are saved to state, in declaration order rather than in an order that could change between runs.

> Derived from project xclconfig (file), spec/plan 20261003081552-e1e07cbe-config-decode. See the project-level record for the full feature.

## What changed in this repo

- **`Decode`** (`decode.go`): `c.Decode(&cfg)` and `xcl.Decode(c, &cfg)` share one two-phase implementation, which resolves every `[]*T` and `*T` field before assigning any of them. `decode_test.go` covers each acceptance criterion in 28 tests.
- **Shared lookup core** (`query.go`): `asType`, `convertibleTo`, `addressableType`, `entitiesOf`, `oneOf` and `typePath` now hold every lookup rule once. `As`, `FindByType`, `FindOne` and `All` are thin typed wrappers over them.
- **New error**: `ErrInvalidDecodeTarget` and `*InvalidDecodeTargetError{Type, Nil}` are in `errors/query_errors.go` and re-exported from `config.go`.
- **Declaration order** (`internal/parser/parser.go`): parsed entities are recorded in first-seen order through `parsed.store`, and the state is built from that order instead of by ranging over a map.
- **Reference coverage**: `query_references_test.go` and the `registered/cache_client` fixture prove that whole-block references to a registered bare-keyword block arrive filled in.
- **Example**: `example/configonly` gathers its configuration into `appConfig` with one `Decode` call. New guards require exactly one `Decode` call and no per-type lookups.
- **Docs**: the README has a "Filling a struct of your own" section, plus notes on the error vocabulary and the two spellings. CHANGELOG.md has a new entry, and `readme_test.go` guards both.

## Why

Applications used to look up each block type separately and assemble their own structure. `Decode` turns that into a single call, so reading a new block type needs only a new field. The parser order fix makes the documented "order they were written" guarantee true, and it gives future features, such as diffing, a stable order to rely on.
