# Diff: report what an apply would change

xcl can now report what an apply would do before you run it. `Config.Diff` takes the same paths as `Apply` and returns a result. The result lists every resource that would be created, updated, replaced or deleted, and every configured value that would change with its old and new value. It also counts the resources that would be left unchanged. Nothing is created, changed, destroyed or saved. Values that are only known after an apply are marked as unknown, and sensitive values stay hidden unless you ask for them to be revealed.

> Derived from project xcl (xclconfig), spec/plan 20261007105731-2388b579-diff. See the project-level record for the full feature.

## What changed in this repo

**New public API**
- **`diff` package:** `Diff`, `Summary`, `Resource`, `Change`, `Action` (create, update, replace, delete), `Path`/`Step`/`StepKind` with string and JSON forms, `Diff.Changed()`, and the `RevealSensitive` option.
- **`Config.Diff(paths []string, options ...diff.Option) (*diff.Diff, error)`:** runs as the new `events.OperationDiff` operation. When it finishes it writes a debug log, "diff complete", with the counts.

**Parser**
- **`Parser.Diff`:** a diff mode of the apply walk, recorded by a concurrency-safe diff recorder.
- **Shared refresh step:** the Read and Changed calls are now a separate refresh step that apply and diff share. Apply's behaviour is unchanged.
- **Field-level comparator:** compares values field by field and masks sensitive values unless they are revealed.
- **Unknown values:** an unknown-aware context hook and a diff decoder, so that values only known after an apply (including the computed fields of resources being updated) are reported as unknown.

**Tests**
- Unit and integration tests in `diff/`, `internal/parser/` and the root package, with new fixtures under `internal/test_fixtures/config/diff/`.
- Diff cases in the sensitive-leak suite.
- An end-to-end suite, `e2e/diff_test.go`, which checks the diff against the apply that follows it.

## Why

Tools built on xcl need to show or act on pending changes, including drift in real infrastructure, before an apply runs. The result is plain data that can be inspected in Go or encoded as JSON.

The diff reuses the apply walk and the providers' read and change checks, so the two cannot disagree about what changes. It never under-reports: an apply never changes a resource the diff did not list.
