# Sensitive values

Fields holding passwords, tokens and other secrets can now be declared `types.Sensitive[T]`. xcl then shows them only as `(sensitive)` in logs, events, errors, configuration text and printed resources, and so does your own `fmt`, `slog` and JSON output, while state and plugins keep the real value and `Reveal()` unwraps it. Assigning a sensitive value to a plain field is refused at validation and at Go conversion, naming the field.

> Derived from project xcl, spec/plan 20261003134528-327e0657-references-and-secrets. See the project-level record for the full feature.

## What changed in this repo

- New public `types.Sensitive[T]`, `NewSensitive`, `SensitiveValue`, `IsRedacted`, `SensitiveMarker`, `SensitiveMark`, `RedactedMark`; `types.Output.SensitivePaths`, `WrapSensitivePaths`, `UnmarshalJSON` and `Format`.
- Generic wrapper hook in the copied `gocty` (marked values become path errors instead of panics) and `ReplaceMarked` encoder option in the copied `gohcl`, both recorded in `UPSTREAM.md`.
- New internal encoder `internal/wire` for state, provider calls, change detection, host callback and query conversion; `StateStore.Save` now receives `json.RawMessage` records (breaking).
- New validation stage rejecting sensitive values in plain fields; output values keep sensitive parts; function errors redact sensitive arguments; event data shows the marker at both levels (breaking for consumers comparing it byte-for-byte with state).
- `xcl.RevealSensitive()`, `logger.WithRevealSensitive(true)`, `TypeMismatchError.Field`.
- Plugin types support seven `Sensitive` instantiations via `schema.KnownTypes()`; others fail loading. The schema type parser handles nested brackets.
- Examples declare their passwords sensitive; README, docs and CHANGELOG updated; leak, round-trip, validation, conversion, encoding and printer tests added.

## Why

Secrets used to be shown wherever xcl or the application printed, logged or reported them. This repo holds the library, examples and docs, so all of the behaviour lands here.
