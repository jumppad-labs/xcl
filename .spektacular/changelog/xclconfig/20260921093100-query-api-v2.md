# Query API v2

Ask a parsed configuration directly for what you want, as your own Go type, in a single call — one
entity by its address, everything of a kind, the one you expect to be unique, or everything of a Go
type. Values a configuration publishes are read by address like anything else and come back as the
value itself. When a lookup cannot be answered it now returns a specific, matchable error instead of
an empty result or a value with half its fields unset, and the configuration object is the only
supported way to reach into a parsed configuration.

> Derived from project xclconfig (file), spec/plan 20260921093100-query-api-v2. See the project-level
> record for the full feature.

## What changed in this repo

**The lookup surface** (`query.go`, `query_methods_go127.go`). `Find`, `FindByType`, `FindOne`, `All`
and `As` as package-level generic functions, plus the same four as generic methods on `*Config`
behind `//go:build go1.27`. Both spellings delegate to one unexported implementation. The module's
declared minimum stays `go 1.25.0`, so the function form is what every example, test and sample uses.

**Published values.** An `output` is retrieved by address, yielding the resolved value rather than the
declaration. `Config.Outputs()` returns every published value keyed by address.

**Error vocabulary** (`errors/query_errors.go`, re-exported from `xcl`). `ErrNotFound`,
`ErrUnknownType`, `ErrNotTypeable`, `ErrNotRegistered`, `ErrTypeMismatch`, `ErrNotAnEntity` and
`ErrNotUnique`, each wrapped by a detail type recoverable with `errors.As` — `NotUniqueError.Count`
reports how many matched. `state.ResourceNotFoundError` answers to `ErrNotFound`;
`plugins.ErrNotFound`, which means the real infrastructure is gone, deliberately matches neither.
`ConfigError` now implements `Unwrap() []error` and `ParserError` carries a `Cause`, so `errors.Is`
and `errors.As` reach a failure nested inside what `Apply` and `Destroy` return.

**Data model.** `types.Meta` gained `Subtype`: `Type` is now always the stanza kind and `Subtype` the
variety, empty for single-label stanzas. `internal/resources.FQRN` gained the same pair, so addresses
carry the variety as their own segment. Type details are consolidated into one `types.TypeInfo`
record held by the registry, which also gained `KnownType`, `RegisterBareType` and `TypePath`.

**A second stanza form.** A top-level item can be declared as `container "nics" {}` alongside
`resource "container" "nics" {}`. They are different types with different addresses — `container.nics`
and `resource.container.nics` — and a type is registered under one form or the other, never both.
The parser asks the registry what it knows instead of matching a fixed list of four keywords.

**State became storage only.** `StateStore` now exchanges plain entities — `Load() ([]any, error)`
and `Save([]any) error` — and `State` is no longer a public type; the container moved to
`internal/parser`. The `state` package parses no addresses and performs no searches. **This is a
breaking change** for anyone implementing `StateStore`, and the only one in this work.

**Removed.** `NewQuerier`, `Querier[T]` and its methods are deleted, not deprecated. Code
constructing them no longer compiles. `Config.GetResources` and `Config.ResourceCount` are renamed
`Entities` and `EntityCount`, with the previous names kept as deprecated aliases returning identical
results.

**Also fixed.** Loading a saved configuration no longer silently drops a record it cannot read — six
skip paths now report, and a dropped record was previously erased from the file on the next save. The
configuration-only example now performs the teardown its documentation and tests always claimed. A
module lookup no longer returns entities of a sibling module whose name shares a prefix.

**Examples, docs and CI.** All three examples use the portable form; the plugin example demonstrates
retrieving a published value by address. The README, `docs/` and the recorded architecture knowledge
describe the current surface. A CI job builds and vets against the pinned minimum Go version on every
change, and the existing job's toolchain pin — which sat below the module's own declared floor — is
corrected.

## Why

The previous surface required constructing a throwaway helper bound to one Go type before every
lookup, then answered badly: a kind query returned an empty result whether or not the question made
sense, a mismatched conversion returned a partially populated value alongside its error, a metadata
failure panicked, and reading a published value meant knowing how outputs are stored. Each of those
failures was silent or misleading. They are now impossible or named, and the surface is short enough
that the obvious way to write a lookup is also the correct one.
