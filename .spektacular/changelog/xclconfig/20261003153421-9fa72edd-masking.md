# Masking sensitive values in state and events

xcl can now encrypt the sensitive values it keeps in state: give it a key with `xcl.WithStateMask(mask.EncryptAES256GCM(key))` and the state file never holds a secret in plain text, while a later run with the same key reads the real values back. Without a key, xcl warns once per apply or destroy that state holds sensitive values unencrypted. Event data now shows each sensitive value through a configurable masker, redacted by default, and can carry real values when explicitly asked to. Developers can write their own maskers.

> Derived from project xcl (xclconfig), spec/plan 20261003153421-9fa72edd-masking. See the project-level record for the full feature.

## What changed in this repo

- New public `mask` package: `Masker`, `Reversible`, the `Masked` envelope (`{"xcl_masked":...,"value":...}`), `Envelope`, `IsMasked`, `IsMaskedObject`, `Unmask`, `Open`, and the built-ins `EncryptAES256GCM`, `HashHMACSHA256`, `Omit`, `Redact`.
- New errors `ErrUnrecoverable`/`UnrecoverableError` and `ErrMaskNotReversible`/`MaskNotReversibleError`, re-exported from `xcl`.
- New options `xcl.WithStateMask`, `xcl.WithEventMask`, `xcl.WithNoEventMask`; the event masker defaults to `mask.Redact()`.
- Both state save sites encrypt through the state masker, both load paths open envelopes, and unopenable state fails with `xcl.ErrUnrecoverable`.
- One plaintext-state warning per Apply or Destroy when no state masker is configured and a sensitive value is written.
- Event data is encoded through the event masker; `EncodeSavedEntity` shows the marker for any masked value.
- The application-config and plugin examples read `XCL_STATE_KEY` to encrypt their state.
- README, `docs/state.md` and `CHANGELOG.md` updated, with content tests; the leak suite runs with encrypted state.

**Breaking:** state encrypted with a key cannot be loaded without the same masker and key; state loading can now fail with `xcl.ErrUnrecoverable`; a sensitive value in event data is now an envelope, `{"xcl_masked":"redact","value":"(sensitive)"}`, rather than a bare string.

## Why

State must keep real values so it can be read back, which left secrets in plain text on disk; and event pipelines could only ever see the fixed marker. Masking is chosen per serialisation call, so one entity can be encrypted in state, redacted in its events and real at its provider in the same apply.
