- `xcl-python:xcl/_transport/subprocess.py` (new) — `SubprocessTransport`:
  - **Construction.** `__init__(program: Path | None = None, *, launcher=None)`. `program` defaults to `program_path()`, defined here and used by selection: `Path(__file__).resolve().parent.parent / "_bin" / ("xcl-core.exe" if win32 else "xcl-core")`. `launcher` defaults to `subprocess.Popen`, and tests inject a launcher that starts the fake engine.
  - **State.** An `_Engine` object holds: `process`, `stdin`, `stdout`, `reader` thread, `waiters: dict[int, _Waiter]`, `handles: set[int]`, `pid` (the host pid at start), `generation`. The transport also holds `self._lock` (`threading.Lock`), `self._next_id` (`itertools.count(1)`), `self._dead_handles: set[int]` (handles of past generations) and `self._forked_handles: set[int]`.
  - **Start** (under the lock, when no engine is running):
    - if the program is missing, raise `EngineNotFoundError`. Selection normally catches this first; this is the backstop;
    - `Popen([program, "--serve"], stdin=PIPE, stdout=PIPE, stderr=None, bufsize=0)`. On POSIX use `close_fds=True` and the same process group. On Windows also call `_windows_job_assign(process)`;
    - start a daemon reader thread;
    - send `GetVersion` directly and check `abi_version == ABI_VERSION` (import from `inprocess`). A mismatch raises `EngineVersionError` with `package="abi 1"` and `engine="abi N"`, after stopping the process;
    - register the `atexit` hook once per transport.
  - **`call(handle, method, request)`**:
    1. Fork check: `os.getpid() != engine.pid`, or a handle in `_forked_handles`, raises `ForkedProcessError(message)` when the handle is non-zero.
    2. A handle in `_dead_handles` raises `EngineExitedError(returncode of that generation)`.
    3. Ensure the engine is running.
    4. Allocate an id, register a `_Waiter` (`threading.Event` plus result), and write `struct.pack(">I", len(frame)) + frame` under a write lock. A `BrokenPipeError` is treated as engine death.
    5. Wait in 0.1 s slices (`event.wait(0.1)` in a loop). Each slice releases the GIL and lets KeyboardInterrupt be delivered on Windows.
    6. If the waiter carries an exit, raise `EngineExitedError`.
    7. Decode the status as signed: `status - (1 << 32) if status >= 1 << 31 else status`.
    8. If `method == "CreateConfig"` and the status is 0, decode `core_pb2.CreateConfigResponse` and add the handle to `engine.handles`.
    9. Return `(status, payload)`.
  - **`release(handle)`**: the same fork and dead checks. A dead or forked handle returns 0 and is forgotten, so closing after an engine death is quiet. Send `Request(method="Release")`, remove the handle from `handles`, and if `handles` is now empty, stop the engine.
  - **Reader thread**: loop `_read_exact(stdout, 4)` then the body, parse `transport_pb2.Response` and hand it to the waiter by id. Unknown ids are ignored. On EOF or OSError:
    1. reap with `process.wait()`;
    2. take the lock and, if this engine is still current, move its handles to `_dead_handles` (mapped to the return code) and clear current;
    3. set every pending waiter to `EngineExitedError(returncode)`.
  - **Stop** (`close()`, the last release, `atexit`):
    1. close stdin, which the engine treats as end of input and releases everything;
    2. `process.wait(timeout=5)`;
    3. on timeout, `process.terminate()` (SIGTERM, or TerminateProcess on Windows) and `wait(timeout=5)`;
    4. then `kill()`.
    5. Join the reader thread briefly.
  - **Fork**: `os.register_at_fork(after_in_child=self._after_fork_in_child)` when available. It moves the current engine's handles to `_forked_handles`, drops the reference to the parent's engine without closing or terminating it (the child's copies of the pipe fds may be closed), clears waiters and recreates both locks.
  - **Windows helpers** `_windows_job_assign(process)`: use `ctypes.windll.kernel32` calls `CreateJobObjectW`, `SetInformationJobObject` (`JobObjectExtendedLimitInformation=9`, `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE=0x2000`) and `AssignProcessToJobObject(job, int(process._handle))`. Keep the job handle on the engine object, so it closes only when the host dies or the engine stops.
  - **`pid` property**: the running engine's pid, or None.

## Performance Considerations

- **Per-call overhead.** A pipe round trip costs about 20–50 µs, against about 5 µs in process. Engine start costs 10–50 ms once per host process (design "What it costs"). This is noise beside parsing and providers.
- **First-use latency.** The first `Config()` must finish within one second on CI runners (success metric, asserted by an integration test). Windows antivirus scanning a fresh executable is the risk; see Open Questions.
- **Package size.** Each wheel carries a static program of about 17 MB (6.5 MB compressed) in place of the 19 MB library. Eight wheels are about 56 MB per release, well within PyPI's limits.
- **Release wall time** should drop now that the four-job toolchain matrix and the macOS runners are gone from the release path. This is checked by hand against the v0.4.0 run.
