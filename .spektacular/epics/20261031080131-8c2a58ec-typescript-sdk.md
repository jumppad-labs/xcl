## Overview

xcl runs from Go and Python today. This epic brings it to TypeScript and JavaScript on Node in the same way Python got it: the TypeScript package runs the same bundled `xcl-core` engine over its standard input and output, so a Node program validates, diffs, applies, loads and destroys configuration exactly as a Go program does, with the same plugins, state and events. Entity types are described as TypeScript classes, much as ORM entities are, as the `typescript-entity-types.md` design settles. The package is published to npm as `xcl-lang`, with one engine package per platform. The epic also closes a gap Python has today: neither SDK has an API reference. Both get a reference generated from their doc comments and an SDK guide on xcl.dev.

The planned specs, in order:

1. TypeScript core SDK
2. TypeScript printing, highlighting and pretty logger (depends on 1)
3. Python SDK reference and guide on xcl.dev
4. TypeScript SDK reference and guide on xcl.dev, with TypeScript tabs on the site (depends on 1 and 2)
