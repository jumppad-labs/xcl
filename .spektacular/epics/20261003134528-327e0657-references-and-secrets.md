# Epic: 20261003134528-327e0657-references-and-secrets

## Overview

xcl currently shows a configuration in ways that misrepresent what the user wrote, or reveal what they would not want shown. References come back as the values they resolved to instead of the addresses the user wrote. A user's own list of dependencies is silently mixed with dependencies xcl worked out for itself. A module's internals can be reached from outside it. Passwords and other secrets appear in plain text in state, events, logs and printed output. This work lets developers who embed xcl show references as written, and keeps user-set dependencies exactly as the user wrote them. It makes a module's outputs the only way to reach inside it. It introduces a way to declare a value sensitive, so that it is protected wherever it leaves the application: masked in events, logs, errors and output by default, and encrypted in state when a key is supplied. Application code still gets the real values, but only by explicitly unwrapping them, so it always knows it is handling a secret.
