# A ready-to-build xcl plugin template

This repository is now a GitHub template for writing xcl plugins. A repository made from it has one working resource, `notes "note"`, which writes a note to a file. Unchanged, it builds, passes its unit and end-to-end tests and applies its sample with nothing else running. The same plugin runs inside an application or as a separate program. Every change is checked automatically, and tagging a version publishes a signed release for every platform that applications install with xcl's GitHub registry.

> Derived from project xcl (github.com/jumppad-labs/xcl), spec/plan 20261009092551-82db0140-plugin-template. See the project-level record for the full feature.

## What changed in this repo

- **Module:** `github.com/jumppad-labs/xcl-plugin-template`, requiring xcl v0.1.1 and testify v1.10.0, with an Apache-2.0 licence and a `.gitignore`.
- **`client/files`:** the `Files` interface, with `Write`, `Chmod`, `Stat` and `Remove` each taking a context, and its local-disk implementation and tests. The Mockery v3 configuration and the generated `MockFiles` double sit beside it.
- **`entities/note.go`:** the `notes "note"` block type.
- **`providers/note.go`:** the provider, with the exported `ReplaceSettings`, an explicit `Changed` and a told-only `Update`. `providers/note_test.go` has one test per rule against a strict double.
- **Plugin type and program:** `plugin.go` holds `notes.Plugin`, with a unit test that `Init` registers the type without touching disk. `cmd/notes/main.go` serves the plugin, and `examples/basic/main.xcl` is the sample.
- **End-to-end tests:**
  - `e2e/` covers the in-process and external lifecycles, and the replace and update plans.
  - `e2e/stateonly` reads applied notes from state using only `entities`.
- **`Makefile`:** `build`, `test`, `lint` (vet, gofmt and pinned staticcheck v0.8.1), `generate` (pinned Mockery v3.8.0), `inprocess`, `external`, `dist`, `release` and `clean`.
- **Workflows:**
  - `.github/workflows/ci.yml` runs build, lint, test and a snapshot dist build.
  - `.github/workflows/current.yml` runs the suite weekly, or by hand, against the latest xcl release.
  - `.github/workflows/release.yml` builds, signs and publishes on `v*` tags, and refuses to run without `GPG_PRIVATE_KEY`.
- **`README.md`:** the author's guide, from "Use this template" to an installed, signed release.

## Why

The template gives plugin authors a working starting point in the standard xcl plugin layout instead of hand-copied examples. Its releases follow exactly the layout the GitHub registry installs.
